# Agent Note: Normalize certificate photo orientation before recognition

Status: implemented
Scope: backend/ocr_app/image_preprocessing.py, backend/ocr_app/documents.py, backend/ocr_app/pipeline.py, requirements-app.lock.txt, scripts, tests, openapi.yaml, SPEC.md, RUNTIME.md
Last-verified: 2026-10-12

## Problem

The user approves automatic orientation and small-angle deskew for diploma and degree photos after the [degree mapping repair](../../implemented/bug-fix/2026-10-12-degree-school-and-award-mapping.md), then approves extending the same preparation to other certificate/card photographs. The existing decoder applies EXIF but does not infer pixel orientation. OCR mistakes and mapping failures are different: image correction can help source recognition but does not replace source-bound field extraction.

## Decision

The CPU helper uses the Apache-2.0 PaddlePaddle PP-LCNet_x1_0_doc_ori official ONNX export, pinned to revision 7330ab7039123e46af2dc03154b9969aa412c61d and SHA256 af9a0a4f317ff0709ce752067807f819cb15d883f8ecad89f28df1c6ee2d9c92. Each view follows its published RGB resize-short256/center224/ImageNet preprocessing and label order 0/90/180/270. Model download is an explicit installation step, never a runtime network call. Missing/corrupt model or unavailable inference dependencies preserve the original direction and surface a bounded warning. Runtime dependencies and [model notices](../../../../scripts/IMAGE-UPRIGHT-NOTICES.md) are pinned separately from the recognition models.

After EXIF, center and full-page padded views must predict the same quarter-turn. At least one score reaches0.90 and both top-two margins reach0.25; these conservative thresholds are not calibrated probabilities. The initial center-only probe gives weak scores for some degrees, motivating full-page agreement rather than lowering the threshold to fit named cases. Blank, tiny or extreme-aspect input avoids unsafe classification/resizing.

Small-angle deskew uses text-sized connected components and a bounded horizontal-projection search, from -12 to12 degrees in0.5-degree steps. A nonzero interior optimum needs at least15% improvement over unrotated projection variance; both page halves need sufficient text, at least10% gain and agreement within1 degree. Otherwise the confirmed quarter-turn is retained without a speculative tilt. Preserve originals, expand the output canvas with white fill rather than crop, and skip a deskew expansion exceeding40 million pixels. Perspective or nonrigid unwarping is outside this implementation.

An explicit allowlist covers DIPLOMA, DEGREE_CERT, ID_CARD_FRONT, ID_CARD_BACK, BANK_CARD, BUSINESS_LICENSE, XUEXIN_DIPLOMA_TABLE, PASSPORT and HOUSEHOLD_REGISTER raster uploads. Native and scanned PDFs, MEDICAL_REPORT and GENERIC retain current decoding. Persist preprocessing angles, model identity, scores, decisions and elapsed CPU time with the encrypted page/result evidence. Scores describe orientation classification, not calibrated OCR field confidence. Two-pass decoding reuses the first correction decision without another classifier/deskew search, so stored preview pixels, dimensions, planned regions and OCR input remain consistent. Task cancellation and the existing overall deadline cover preprocessing too.

Bank photo upload and manual crop/rotation recovery keep their existing contracts. A legacy successful admission prediction is reusable only if the preparation makes no quarter-turn or deskew change. Changed pixels require fresh recognition rather than attaching an old prediction to a corrected preview. Sparse card-number strips retain conservative abstention; no card-specific threshold is lowered. Missing real samples qualify only the processing flow, not recognition accuracy. The approved [bank ROI orientation repair](../../implemented/bug-fix/2026-10-12-bank-card-roi-orientation.md) adds a bank-only direction-evidence path; the shared model, thresholds and complete-photo contract remain owned here.

Separate CPU and recognition probes retain source hashes, known transformations, encrypted derived inputs/results and unsuccessful outcomes. Fresh recognition comparisons use a serial single-resident isolated GLM run, retain failed/truncated measurements, and do not mix with production concurrency or old accuracy results.

## Alternatives considered

- EXIF only: minimal and lossless when metadata is correct, but cannot infer rotated pixels or a tilted scan. Preserve EXIF as the first step and add conservative pixel analysis.
- Recognize all four rotations with GLM/Paddle: uses current models and can choose the clearest output, but multiplies inference cost and field completeness is not proof of correct orientation. Use a dedicated small classifier first.
- Enable Paddle's whole preprocessing pipeline including UVDoc: mature and handles broader distortions, but adds unapproved perspective/nonrigid changes and runtime dependencies. Start with the pinned orientation export and bounded deskew.
- Always rotate by a geometric angle estimate: maximizes apparent correction coverage, but a border, portrait or seal can dominate. Require text evidence and agreement, otherwise abstain.
- Enable preparation for every material type: one broad condition is simpler, but adds unrequested changes to medical/PDF evidence and unknown generic layouts. Use the explicit certificate/card allowlist while keeping the same conservative detector.

## Consequences

Orientation scores are uncalibrated and small-angle estimates can be unreliable on sparse or decorative pages. Rotation resampling can reduce fine-detail quality even when geometric correction is correct. Keep right-angle rotations lossless, deskew conservative, and original inputs recoverable. Windows measurements do not qualify Mac performance.
