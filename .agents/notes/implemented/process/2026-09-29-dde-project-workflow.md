# Agent Note: Keep DDE rules and verification in the project

Status: implemented
Scope: scripts, .agents/skills/dde, skills-lock.json, package.json, AGENTS.md, CLAUDE.md, .gitignore, .gitattributes
Last-verified: 2026-10-08

## Problem

Architecture and benchmark decisions live in conversation and separate reports. Future changes need a discoverable record of rationale, alternatives and verification without adding an application dependency.

## Decision

NianLog/DDE is installed locally for Codex and Claude Code. The project copies the upstream scripts unchanged into scripts/ and retains their license in scripts/DDE-LICENSE.txt. A private package declares Node >= 18, no runtime or development dependencies, and npm run verify delegates to npx tsx scripts/notes.ts verify. AGENTS.md and CLAUDE.md require notes for non-trivial changes and verification before delivery or commit.

The notes tree has proposed, implemented, rejected and archived lifecycle directories. Class directories are created only when used and are limited to feature, bug-fix, simplification, architecture, process and testing. The asset index is generated by the upstream CLI.

## Decision audit

The [automatic-layout experiment](../testing/2026-09-29-automatic-layout-evaluation.md) is the first note. It is unrelated to tooling ownership and is now implemented as an offline experiment; production runtime is a separate architecture decision, with the first runtime slice now implemented. No older process decision exists to supersede.

## Alternatives considered

- A global-only Skill installation avoids project files, but collaborators would lack the same local rules and scripts. The project installation makes them available with the workspace.
- Handwritten validation could be smaller, but would diverge from DDE lifecycle and metadata checks. The copied upstream scripts provide the standard checks.

## Consequences

Decisions have a searchable lifecycle and mechanical checks. Existing OCR scripts and reports remain intact. This adds source tooling and instruction files, but no application package dependencies.

The scripts use Node builtins, but npx obtains tsx on first use. An empty npm cache needs network access; this is not a fully offline bootstrap. The initial official npm registry connection failed, so tsx was cached using a command-local npmmirror registry argument. Global and project registry configuration remain unchanged; the exact original npx command subsequently succeeds.

The user authorizes an initial source commit to the empty Gitee repository bi_li258/zjsb. Git is initialized without hooks or changes to global configuration. Git text files use LF via .gitattributes so sealed archive hashes survive Windows clones. Empty lifecycle directories retain .gitkeep files. Source, tests, locks and DDE assets are committed; models, environments, runtime keys/business data, outputs, local recovery trees and original materials are excluded by .gitignore. Historical output links describe local-only evidence rather than files available in a clean clone. The frontend-removal checkpoint stages the verified pre-HR-field backend/SPEC/OpenAPI snapshots while current HR changes remain in the working tree. Archive baseline checks use Git after the initial commit; before HEAD exists, only the upstream on-disk checks are available. Node >= 18 is the upstream compatibility target; this machine's execution is validated on Node v24.21.0, not separately on Node 18.
