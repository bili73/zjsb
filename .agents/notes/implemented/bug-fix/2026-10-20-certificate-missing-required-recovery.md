# Agent Note: Retry one observed local certificate region for missing required fields

Status: implemented
Scope: backend/ocr_app/pipeline.py, backend/ocr_app, backend/runtime_worker.py, tests, scripts, SPEC.md, openapi.yaml, FRONTEND_FIELDS.md, RUNTIME.md, CHANGELOG.md
Last-verified: 2026-10-20

## Problem

A fresh GLM diploma attempt ends normally but omits an entire specialization value. The source image contains the value, older complete OCR maps correctly through the current parser, and the latest attempt is neither cached nor truncated. Current EOS success ends fallback before required-field extraction. Existing CPU OCR finds the specialization, its neighboring printed label and their observed positions. Normal generation termination proves neither semantic completeness nor that required fields were read.

## Decision

The pipeline inspects missing editable required fields after primary OCR for single-page DIPLOMA/DEGREE_CERT documents. It uses the administrator required-field snapshot at recognition start, excluding optional fields and fields with existing conflicting candidates. The bundled CPU text helper runs on a bounded-size image to locate printed labels and neighboring rows; one bounded local crop contains observed context rather than fixed specimen coordinates. If no suitable crop exists, fields stay missing for manual entry. Other entry pipelines, multi-page certificates and native-only documents keep their existing paths in this first qualification.

The pipeline appends at most one recovery region and calls the existing primary GLM recognizer once, with a20-second generation soft limit inside the same180-second active task budget and normal queue ownership. There is no retry of that recovery call or loop per field. This missing-field recovery takes no Paddle call: the user points out cross-lane waiting behind medical work, and GLM successfully reads the identical context crop in the isolated comparison. Existing failure/truncation fallback is unchanged. Primary OCR and all attempts remain available. Only EOS supplemental output can supply previously missing target fields through the ordinary certificate parser; crop position or a known sample answer never supplies a value. Filled/ambiguous primary fields remain authoritative and unchanged; conflicts inside supplemental output remain candidates. Incomplete/failed supplemental text remains raw evidence and does not fill fields. A failed lookup or optional retry leaves the original result reviewable; cancellation, exhausted task deadline and supervisor failures retain existing terminal semantics.

The recovery region is added before the final primary progress checkpoint is published, so real region counts remain monotonic. Supplemental sources use the new region ID and coordinates in the full corrected page. Confidence remains uncalibrated and manual/export requirements stay in force. Historical encrypted results, human edits, IDs/revisions, original samples and previous failures are not rewritten. No new model/dependency, frontend control, database migration or Mac online operation is needed.

Observed page context extends to width/height at most2.3 when possible, avoiding extreme horizontal strips while retaining the65-percent area cap. The first thin-crop Paddle experiment repeats and abstains; the enlarged-context Paddle experiment succeeds, as does GLM on exactly the same bytes. These trials stay separate and are not relabelled as final-default tests. No hardcoded specimen coordinates or desired value enters crop planning or model prompts.

## Alternatives considered

- Loosen the specialization regex: cheap when raw text exists, but verified replay already extracts the complete older text and cannot recover words missing from OCR.
- Rerun the entire document or every missing field: broad coverage, but repeats already successful work and can monopolize queues. Use one observed context crop per document.
- Use quick CPU transcription directly as business truth: fastest and reads this example, but bypasses the existing recognizer/parser evidence path and can introduce cropped-field misassociation. Use it for crop geometry, with source-bound model output parsed normally.
- Always invoke both large models: may rescue omissions without a missing-field check, but adds latency even for complete results. Trigger recovery only for missing configured required fields.
- Use Paddle for the one missing-field retry: complementary recognition succeeds with the enlarged crop, but takes the medical queue and can introduce cross-model waiting into otherwise independent certificate work. The identical crop also succeeds with GLM; reuse GLM and preserve Paddle only in the existing error fallback path.
- Add a new semantic model or known-value fallback: can populate more fields but adds deployment cost or invents content. Keep unsupported values missing for manual entry.

## Consequences

Missing fields can recover without a whole-page rerun or a new dependency. This recovery uses the existing GLM FIFO, avoiding an additional dependency on the medical Paddle queue; it does not skip queued GLM requests or alter the original primary error fallback. CPU labels or context may still be missed, and one crop cannot guarantee recovery of every distant missing field. The fallback intentionally abstains when a bounded crop cannot be established. Added layout and queue wait consume the original task budget. A single known specimen qualifies this failure mode, not all certificates, Mac deployment or general OCR accuracy. Historical task values and manual corrections are not automatically changed; users explicitly rerun or upload to use the rule. Shared frontend work remains outside this change.
